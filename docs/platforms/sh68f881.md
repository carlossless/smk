# SH68F881 Support

32KB of flash with a 4KB ISP bootloader at `0x7000`, 2304 bytes of xdata, and a separate
2KB EEPROM-like data block. Runs at 12MHz.

## MCU

- [x] Regulator (REGCON, brought up with the PLL)
- [x] CPU Clock (PLL, 12MHz SYSCLK)
- [x] GPIO
- [x] UART
- [ ] PWM (PWM0CON..PWM2CON are there, no board here drives them)
- [x] USB
- [x] SPI
- [x] Flash and EEPROM read/write (SSP)
- [x] ISP (jump)
- [x] EEPROM (settings store)
- [x] Sleep (Power-Down; an external interrupt, Timer3 or the base timer is the only way
      back, USB is not, so a board has to arm a wake pin before it sleeps. No keyboard
      here opts in yet)

## Stores

`flash.c` is the SSP engine, and it is the same on every part: IB_CON2..5 take a fixed key to
arm one byte-program or one sector-erase, and `FLASHCON.FAC` swaps the data window into the
MOVC address space. What differs is what there is to address, which is the part's `nvm_hw.h`:

| store | where | survives a reflash |
| --- | --- | --- |
| EEPROM-like block | 2 KB of 256-byte sectors from `0x0000` in the FAC window | yes |
| information block | `0x1000` and up in the same window | yes |

## On-chip buses

The pins below are the part's, not a board's choice: the block takes them over when it is
enabled, so a board whose matrix or backlight already owns one cannot use that block.

| block | pins | driver |
| --- | --- | --- |
| EUART | TXD P0.0, RXD P0.1 | `uart.c`, `-Ddebug_sink=uart` |
| SPI | MOSI P2.4, MISO P2.5, SCK P2.6, SS P2.7 | `spi.c` |
| TWI | none on this part | `bb_i2c.c` on any two pins |

SPR divides fSYS by 4 through 128, and saturates there: codes 101 through 111 all give
128. The EUART sits at `0x98`-`0x9d`, which is the USB block on page 1, so the driver
pins the page around every access. The genesis-thor-300 leaves both pin sets free.

SinoWealth publishes no datasheet for this part. The SH79F6488/SH79F6489 one describes a
very close relative and is what the register map here was built from, but it does not

against the hardware.
